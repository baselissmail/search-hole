## Purpose

- MCPJam Inspector is "the testing & evaluations platform for MCP server developers" (`README.md`). It runs three ways: `npx @mcpjam/inspector` (local, binds 127.0.0.1:6274), an Electron desktop app (`mcpjam-inspector/forge.config.ts`) and a hosted app. Inspector package v3.18.0, SDK 10.2.0, CLI 6.0.1.
- Features that matter to us: MCP Apps and ChatGPT Apps rendering in a sandboxed iframe, a CSP workbench, emulation of 16+ hosts (19 rows in `sdk/src/host-compat/catalog.generated.ts`: Claude, Claude Code, ChatGPT, Cursor, Codex, VS Code, Copilot, Goose, Slack...), MCP protocol-version pinning incl. 2026-07-28, conformance suites, LLM evals, a CLI (`mcpjam`) and SDK (`@mcpjam/sdk`) for CI.
- Role for search-hole: (a) the closest thing to a test harness for the in-chat receipt panel, (b) a dated, probe-captured catalog of what each host really supports, (c) reusable conformance/eval tooling for the gateway. The clone is shallow (1 commit).
- Path shorthand below: all paths are relative to the ref root; `INS/` = the `mcpjam-inspector/` package directory inside it (so `INS/server/index.ts` is `research/refs/mcpjam-inspector/mcpjam-inspector/server/index.ts`). Their own docs `INS/client/src/components/chat-v2/thread/MCP_APPS_RENDERING.md` and `DOUBLE_IFRAME_SANDBOX.md` are partly stale (they describe `srcdoc` mounting); trust the code cited here.

## Architecture sketch

- npm-workspaces monorepo, no Turbo/Nx: root `package.json` lists 13 workspaces (evaluators, sdk, cli, mcpjam-inspector, design-system, chat-ui, widget-react, soundcheck, mcp, slack-app, surface-core, discord-app, vitest). Node >=22 (`INS/package.json` engines). Build order is a hand-written `npm run build -w` chain; releases use Changesets (`.changeset/config.json`, private packages in `ignore`).
- Layering: `sdk/` (MCPClientManager, conformance, evals, host-compat catalog, widget-runtime bridge) -> `widget-react/` + `chat-ui/` (React renderers, `check-tier-imports.mjs` enforces what each tier may import) -> `INS/` (Vite 8 + React 19.3 SPA in `INS/client`, Hono 4.13 API in `INS/server`, shared types in `INS/shared`). `cli/` and `mcp/` (Cloudflare Worker MCP server) reuse `sdk/`.
- Local process model: `INS/bin/start.js` picks port 6274 (fail fast if taken), spawns `node dist/server/index.js` with env `MCPJAM_SESSION_TOKEN` and `MCPJAM_INSPECTOR_PARENT_PID`, polls the port (200 ms, 30 s cap), opens the browser. The server polls `process.ppid` every 1 s and shuts itself down if the launcher died (`INS/server/index.ts`, `orphanCheckInterval`). Server bundle = tsup, ESM, target node22, `splitting:false`, deps left external (`INS/server/tsup.config.ts`), so it is not self-contained and needs `node` on PATH.
- One origin serves both SPA and `/api/*`; there is no daemon shared between several CLI instances (the CLI "attaches" through a per-port discovery file, see Data model).

## Key modules and data flow

MCP Apps render path (the part most relevant to the receipt panel):
- Detect: `detectUIType` in `widget-react/src/mcp-apps-utils.ts` classifies a tool as MCP_APPS (`_meta.ui.resourceUri`, also the deprecated flat `_meta["ui/resourceUri"]`, `sdk/src/widget-runtime/tool-ui-resource.ts`), OPENAI_SDK (`openai/outputTemplate`) or both.
- Fetch: `POST /api/apps/mcp-apps/widget-content` (`INS/server/routes/apps/mcp-apps/index.ts`) requires an explicit `cspMode` (`permissive` | `widget-declared`, else 400), reads the `ui://` resource through MCPClientManager, accepts mime `text/html;profile=mcp-app` plus legacy `text/html+skybridge` and `text/html` (warns), else 415. HTML comes from `text` or base64 `blob`.
- Metadata precedence is per field: content-item `_meta.ui` -> `resources/list` entry `_meta.ui` -> legacy `openai/widget*` keys (`INS/server/utils/ui-resource-meta.ts`). It skips the extra `resources/list` call when the content item already declares everything (`canSkipListingLookup`). `ui.domain` is advisory only; the inspector derives its own view origin.
- Double iframe: host SPA -> outer iframe on a different origin -> proxy page `sandbox-proxy.html` (`INS/server/routes/apps/mcp-apps/`) -> inner guest iframe. Local origin separation = swapping `localhost` <-> `127.0.0.1`, optionally a per-server `<16hex>.localhost` label; hosted = `SANDBOX_ORIGIN` (`widget-react/src/sandboxed-iframe.tsx`). Outer `sandbox=` default `allow-scripts allow-same-origin allow-forms allow-popups allow-popups-to-escape-sandbox` (`sdk/src/widget-runtime/iframe-sandbox-policy.ts`).
- Handshake (JSON-RPC 2.0 over postMessage): proxy -> host `ui/notifications/sandbox-proxy-ready`; host -> proxy `ui/notifications/sandbox-resource-ready` carrying `{html, sandbox, csp, permissions, sandboxAttrs, cspDirectives, cspSubtypePolicy, permissive, colorScheme, mountMode}`. Proxy only accepts messages from pinned host origins (patterns templated into the page at serve time, first accepted origin is locked, replies use that exact targetOrigin) and the route sends `frame-ancestors` with the same list (`INS/server/routes/apps/mcp-apps/sandbox-proxy-html.ts`).
- Mount: the proxy builds a CSP, injects it as `<meta http-equiv="Content-Security-Policy">` plus a `securitypolicyviolation` listener, then writes the HTML into a fresh blank inner iframe via `document.open/write/close` so the view has a real URL and origin (their comment: this is how claude.ai and Claude Desktop mount views). `mountMode:"opaque"` uses `srcdoc` without `allow-same-origin` (storage throws, `Origin: null`), used to emulate Copilot-like hosts. Written documents without `<!DOCTYPE html>` render in quirks mode (`sandbox-proxy.html` `mountInner`, `docs/inspector/view-origins.mdx`).
- Bridge: host creates `AppBridge` from `@modelcontextprotocol/ext-apps` (lock: 1.7.5, peer dep `@modelcontextprotocol/sdk ^1.29`) over `PostMessageTransport`, then `sendToolInput`, `sendToolResult`, `setHostContext` (`sdk/src/widget-runtime/host-app-bridge.ts`, `createHostAppBridge`, `registerHostBridgeHandlers`). Policy "advertise = enforce": a handler is installed only if its host capability is true. `tools/call` from the app is rejected when the tool is `visibility:["model"]` only (`isVisibleToModelOnly`, same file ~L429).
- ChatGPT path: for `openai/outputTemplate` tools the same pipeline injects a `window.openai` shim (`sdk/src/McpAppsOpenAICompatibleRuntime.ts`, `ChatGptAppsRuntime.ts`) that defines ONLY the methods the active host profile supports (13: callTool, sendFollowUpMessage, setWidgetState, requestDisplayMode, notifyIntrinsicHeight, openExternal, requestModal, uploadFile, getFileDownloadUrl, requestCheckout, requestClose...), so widgets' feature detection behaves like the real host.
- Launching stdio servers: `MCPClientManager.connectViaStdio` (`sdk/src/mcp-client-manager/MCPClientManager.ts` ~L2824) builds `StdioClientTransport` from `@modelcontextprotocol/client/stdio` with `command, args, cwd, stderr` and env = the WHOLE `process.env` (values starting with `()`, i.e. exported shell functions, dropped) overlaid with `config.env`; it does not use the SDK's restricted default env, so every secret in the user's shell reaches the child. Connect has a timeout and an AbortSignal; on failure the last 16 KiB of child stderr is appended to the error message. A pinned 2026-07-28 version is HTTP-only (stdio always negotiates `auto`; the factory throws `StatelessRequiresHttpTransport` if forced).
- Keys: provider (BYOK) API keys for the chat playground live in browser `localStorage` and are sent per request (`INS/client/src/hooks/use-ai-provider-keys.ts`); MCP-server secrets are vault-backed in the hosted product, and a revealed credential's headers are attached only to requests whose origin is bound to it, hop by hop across redirects because Fetch strips only `Authorization`/cookies, not vendor headers like `x-api-key` (`INS/server/utils/credential-header-binding.ts`). A browser-agent feature lets the model write `{{secret:NAME}}` placeholders that are substituted at the last moment and scrubbed from results, so the model never sees the value (`INS/docs/browser-secret-placeholders.md`).
- Headless harness: `INS/server/utils/mcp-app-browser-harness.ts` mounts a widget in Playwright Chromium (fresh context, downloads off, one tab, default-deny network with allowlist), using the same proxy CSP builder, and returns `WidgetRenderStatus` (rendered, mount_failed, bridge_timeout, blank_screenshot, browser_unavailable...), screenshots, console errors and captured widget `tools/call`s; `executeAction` scripts clicks/typing.

## Data model and storage

- No SQLite. Projects, servers, hosts, suites and runs live in a Convex cloud backend even in local mode (`INS/client/src/state/storage.ts`: legacy localStorage state "collapsed to no-ops"; `CONTRIBUTING.md` Convex setup). This conflicts with our local-first principle, so nothing here is a storage model; hosted/guest tokens and cloud features are deliberately avoided.
- Local files: `~/.mcpjam/` for secrets (`INS/server/utils/local-secret-store.ts`: env var wins, else 32 random bytes hex persisted to a file) and `~/.mcpjam/inspector/<port>.json` (pid, port, token, startedAt) for CLI attach (`INS/server/services/inspector-runtime.ts`, EE: idea only: dir 0700, file 0600, `wx` exclusive create, temp-file + rename, removed on close).
- Browser: the access token sits in `localStorage["mcpjam.local-access"]` (`INS/client/src/lib/access-link.ts`).
- Host profile schema (the valuable data model): `HostCompatProfile {id, label, provenance: vendor-doc|probe|assumed, verifiedAt, rendersMcpApps, rendersOpenAiApps, supportedProtocolVersions, capabilities, imageSupport}` (`sdk/src/host-compat/types.ts`); catalog entries add `mcpProfile.initialize {supportedProtocolVersions, clientInfo}`, `apps.sandbox {csp.mode, permissions, sandboxAttrs, sameOriginAppIframe, allowFeatures, browserStorage}`, `apps.mcpAppsOverrides` (17 booleans + `availableDisplayModes` + `widgetDisplayModeRequests`) and a `toolResult` forwarding policy (`sdk/src/host-compat/catalog.generated.ts`, generated from the backend seed; drift guard `check:host-catalog-fallback`).

## Config format

- Server config = union of stdio `{command, args, env, cwd, stderr}` and http `{url, requestInit, authProvider, ...}`; `mcpProtocolVersion` per server (HTTP only) or host default, `"auto"` = unpinned (`sdk/src/mcp-client-manager/types.ts`, `docs/inspector/protocol-versions.mdx`).
- Eval suite files: YAML (JSON accepted, single document only, no format sniffing), `schemaVersion: "2"`, `suite`, `target.servers`, `defaults {model, iterations: 2, passThreshold: 0.8, temperature: 0, judge.enabled}`, `cases[].steps[]` of kind `prompt` or `assert` (assertions such as `toolCalledAtLeastOnce`, `noToolErrors`, `finalAssistantMessageNonEmpty`), findings are `{code, path, message}` sorted for byte-stable CI diffs (`.mcpjam/evals/mcpjam-mcp.yaml`, `sdk/src/suite-file-loader.ts`).
- Launcher env: `PORT`, `HOST`, `MCPJAM_SESSION_TOKEN` (>=24 chars `[A-Za-z0-9_-]`), `MCPJAM_ALLOWED_HOSTS`, `ALLOWED_ORIGINS`, `MCPJAM_ALLOW_WILDCARD_ORIGINS`, `SANDBOX_HOSTS`, `DOCKER_CONTAINER`.

## Testing strategy

- Gate order: `npm test` runs fail-closed Node guard scripts first (`scripts/check-runtime-guards.mjs`: a missing scan root, zero files scanned or an unreadable path is a FAILURE; it replaced `! rg ...` which passed when rg was absent), then workspaces in parallel (Vitest 4, `node --test` for scripts), then Playwright e2e (smoke, local-access, OAuth debugger, visual archives uploaded to Chromatic). ~3,700 test files in the tree. `slop:check` ratchets counts of `as any`, `as unknown as`, TS/eslint suppressions, empty or swallowed catches, server `console`, history comments and filler UI copy (`scripts/slop/rules.mjs`); repo-hygiene caps source files at 800 lines.
- Security tests are structural: the Node twin of the CSP builder is asserted byte-identical to the one extracted from the HTML (`INS/server/utils/__tests__/sandbox-proxy-csp.test.ts`), a bundle-freshness test (`INS/server/__tests__/sandbox-proxy-bundle-fresh.test.ts`), host-partition tests, and `INS/server/routes/web/__tests__/auth-coverage.test.ts`, a BEHAVIOURAL test that calls every route with no credential and fails on any 2xx unless the route is listed with a reason (written after route MJ-002 shipped without its auth middleware; a missing `.use()` line is invisible in review).
- How it tests servers (evals feature): (1) deterministic unit tests with `MCPClientManager` against `@modelcontextprotocol/server-everything` (`sdk/README.md`); (2) conformance suites: protocol (legacy + modern, HTTP only), apps (7 checks: `ui-tools-present`, `ui-tool-metadata-valid`, `ui-tool-input-schema-valid`, `ui-listed-resources-valid`, `ui-resources-readable`, `ui-resource-contents-valid`, `ui-resource-meta-valid`; works on stdio), OAuth, tasks (`sdk/src/mcp-conformance/transport-support.ts`, `sdk/src/apps-conformance/`); JUnit XML reporter (`sdk/src/conformance-reporting.ts`); vendored JSON Schemas for 4 spec revisions incl. `mcp-2026-07-28.json` (`sdk/src/mcp-conformance/schemas/`); (3) LLM evals: `EvalTest.run(runner,{iterations, concurrency:5, retries:0, timeoutMs:30000})`, `accuracy()`, `HostRunner`, optional judge, per-host emulation, widget interaction steps (`sdk/src/EvalTest.ts`, `docs/inspector/evals.mdx`).
- Modern-protocol conformance checks worth mirroring (ids in `sdk/src/conformance-catalog.ts`): no `Mcp-Session-Id` minted, `resultType` on every result, `ttlMs` int >=0 and `cacheScope` public|private on all six cacheable ops, header/body mismatch -> HTTP 400 + -32020, unsupported envelope version -> -32022 naming supported versions, removed methods -> -32601/404, header names case-insensitive, `structuredContent` validates against `outputSchema`. Fixture server `INS/test-servers/stateless-mcp-server.ts` and `docs/inspector/protocol-versions.mdx` still say -32004 for an unsupported version (older RC value, inferred), so pin error codes to the final 2026-07-28 schema, not to either.
- Host-readiness lints tied to Claude's published docs, pinned by a manifest with drift check (`sdk/src/claude-readiness/manifest.ts`, `npm run claude-policy:check`): tool names <=64 chars, `annotations.title` on every tool (their MCP server notes the directory reads only `annotations.title`), read/write hints present and consistent, no tool mixing safe and unsafe ops, no free-string operation parameter; apps: mime profile, `resourceUri` modern, CSP names only needed hosts, doctype, 320 px min width, 44 px touch targets, first paint 3000 ms (`sdk/src/claude-readiness/profile.ts`).

## UX patterns worth copying

- Access link: the token rides in the URL fragment (`#token=...&tab=...`), never reaches the server or Referer, and the SPA removes it with `history.replaceState` before analytics init; the terminal prints "Keep this link private" (`INS/bin/access-link.mjs`, `INS/client/src/lib/access-link.ts`).
- Per-host verdict pill (Works / Degraded / Blocked / Unknown) with provenance label ("Verified from vendor docs", "Probe-captured", "Best-effort - unverified"), expandable findings with remediation, and a "Test" button that opens the playground already set to that host (`docs/inspector/host-compat.mdx`). Unknown is never shown as Works.
- CSP Workbench (Findings, Policy Diff, Sandbox Stack tabs; "View origin" with copy button) turns each `securitypolicyviolation` into the `_meta.ui.csp` field to patch (`INS/client/src/components/chat-v2/thread/csp-workbench/classify.ts`, `directiveToField`).
- Playground controls: theme light/dark, display mode, device type, safe-area insets, per-host style variables and a JSON-RPC traffic log per widget; error copy names the exact origin or directive that was refused.
- Design tokens generated from one source with `design:check` / `design:lint` drift gates (`DESIGN.md`).

## Performance tricks

- Proxy HTML (~40 KB) rendered once and memoised; placeholders replaced with function replacers so `$&` in shim source cannot corrupt output (`sandbox-proxy-html.ts`).
- Static HTML shipped as a generated TS string constant (`INS/scripts/bundle-sandbox-proxy-html.js`, `mcp/scripts/bundle-mcp-app-html.mjs` -> `McpAppsHtml.bundled.ts`) so a bundled server or Worker needs no filesystem read; a freshness test catches stale output.
- Lazy Chromium launch on first render; stdio stderr kept as a 16,384-char tail only for connect errors (`MCPClientManager.createStdioStderrDrain`); `unref()`ed timers. The upstream v2 client serves cacheable verbs (`tools/list`, `resources/read`...) from its own cache with zero wire traffic whenever the server sent `ttlMs > 0` (`cacheMode:"use"` default; hint-less results are stored but never served), and MCPJam adds an observer so the UI can show "served from cache" instead of faking a request (`sdk/src/mcp-client-manager/observable-response-cache.ts`).

## Implications for search-hole

- [mcp-tool-surface] Receipt panel must degrade by host: Cursor and VS Code offer inline only, Claude has no pip, Cursor/Slack/VS Code omit `safeAreaInsets`, Cursor probe sent no `styles.variables`, Goose/Gemini lack `serverTools` (so `app.callServerTool` for `apply_rule` fails), Cursor/Slack/Goose lack `updateModelContext`, Claude ignores `frameDomains`/`baseUriDomains` (`sdk/src/host-compat/capabilities.ts`). Feature-detect `hostCapabilities`, ship hard-coded fallback CSS variables, and print the CLI command ("searchhole block ...") when a button cannot work.
- [ui-ux] Hard requirements for the receipt HTML from MCPJam's Claude profile (`claude-readiness/profile.ts`, `docs/inspector/view-origins.mdx`): start with `<!DOCTYPE html>` (written-document mount is quirks mode otherwise), usable at 320 px, 44 px touch targets, first paint < 3 s, mime `text/html;profile=mcp-app`; our addition: set `color-scheme`. Claude Desktop 1.1.1520 sends 76 CSS variables (we assumed ~70) and its capture resolves `light-dark()` to RGBA, so tolerate both forms (`INS/client/src/config/claude-desktop-client-context.ts`). Claude's font needs `https://assets.claude.ai`; MCPJam's emulation ships empty font CSS so fonts cannot be tested there.
- [testing] Test the panel in three layers: (1) `@mcpjam/sdk` apps-conformance against our gateway over stdio in CI (works on stdio), (2) our own Playwright host page that reuses the proxy pattern (different-origin proxy, CSP `<meta>`, AppBridge) with capability matrices copied from `capabilities.ts` and a CSP-violation assertion, (3) manual runs in `npx @mcpjam/inspector` pointed at the gateway. Do not claim real-host verification: they label emulation "prototype - static checks".
- [dual-protocol] MCPJam's default is `{mode:"auto"}`: probe `server/discover`, fall back to `initialize` on any non-definitive modern signal; on stdio the probe runs on a sibling process, i.e. the gateway binary is spawned twice per connect (`sdk/src/mcp-client-manager/version-negotiation.ts`). Keep gateway startup cheap and side-effect free (no migration lock, no list-refresh lease before the first real request) and make discover answerable in well under a second.
- [dual-protocol] Their probe-captured profiles for Claude, Claude Code, ChatGPT, Codex and VS Code list `initialize.supportedProtocolVersions` of 2025-03-26..2025-11-25 only, while the top-level host field adds 2026-07-28 (`catalog.generated.ts`, claude-code row). The lists are ascending and described as order-sensitive, so this is weak evidence (inferred), but it contradicts a flat "Claude Code negotiates 2026-07-28". Keep the legacy `initialize` path tested in CI, not only the stateless one.
- [session-definition] Probe-captured `clientInfo` per host: claude.ai and Claude Desktop both send `claude-ai` 0.1.0 (indistinguishable), Claude Code `claude-code` 2.1.310, ChatGPT `openai-mcp`, Codex `openai-mcp (Codex)`, Cursor `cursor-vscode`, VS Code `Visual Studio Code`, Goose `goose-desktop` (`catalog.generated.ts`). Use it to label `sessions.client`, never to decide trust.
- [mcp-tool-surface] Client-side caching bites a gateway whose tool list or descriptions can change: with SDK v2 clients any `ttlMs > 0` on `tools/list`/`resources/read` means no request leaves the client until it expires. Send `ttlMs:0` (or a short value) on `tools/list` and on the `ui://` receipt resource in dev, and a deliberate value in prod; also keep `cacheScope` correct (`private` for anything user-specific such as rules).
- [security] Dashboard hardening checklist confirmed by a working implementation: bind 127.0.0.1 (0.0.0.0 only inside Docker), 24-byte random token, timing-safe compare, token passed to the child via env then deleted from `process.env` so grandchildren do not inherit it (idea from EE `services/session-token.ts`, not copied), `X-MCP-Session-Auth: Bearer` header with `?_token=` only for SSE, Origin allowlist with exact scheme+port incl. `[::1]` (absent Origin allowed, token still required), Host-header check before serving anything token-related, `/api/session-token` validates but never discloses (`INS/server/middleware/session-auth.ts`, `origin-validation.ts`, `utils/localhost-check.ts`). Adopt the exact-match vs trailing-slash rule for unauthenticated route lists and an auth-coverage test.
- [key-storage] Engine keys (Brave `X-Subscription-Token`, Exa `x-api-key`, Kagi, Tavily) are the same class as MCPJam's vendor-header secrets: bind each key to its engine origin and strip it on any cross-origin redirect hop in our fetch layer, because undici/`fetch` only drops `Authorization`. Never keep keys in browser storage (MCPJam keeps BYOK keys in `localStorage`); the dashboard should only ever see per-engine health, as the plan already says.
- [security] Stdio child env: MCPJam hands the child the entire parent environment. If the gateway ever spawns helpers (a dashboard process, `doctor` probes) pass an explicit allowlist and drop the dashboard session token and engine keys that the helper does not need.
- [security] Log hygiene: a central credential-URL registry plus scrubber used by every log/telemetry sink, with a CI test that fails when a route param named like token/secret/code/key is unregistered (`INS/shared/credential-urls.ts`). Copy the pattern for dashboard logs. Do not copy `local-secret-store.ts`, which writes the secret then `chmod`s it (brief window at default umask); create files with mode 0600 at open.
- [security] The `visibility:["model"]` guard exists only in the host bridge; an app-only `apply_rule` is only as safe as the host's `respectToolVisibility`. Treat `apply_rule` as callable by a hostile model: require a one-time confirmation token minted by the panel/dashboard and re-validated in the gateway (inferred design).
- [runtime-packaging] Embed the built single-file receipt HTML into the gateway bundle as a generated string constant (same trick as `McpAppsHtml.bundled.ts`) plus a freshness test; avoids filesystem reads in a `bun compile` or single-file bundle. MCPJam itself requires `node` on PATH and keeps deps external, so it is not a packaging model.
- [dashboard-process-model] Useful ideas: fixed port with fail-fast, readiness polling, child exit when the parent dies (poll ppid), same-user discovery file for attach. Our dashboard should outlive a gateway, so use a lockfile/lease instead of parent-death shutdown.
- [monorepo-shape] Fail-closed guard scripts, a file-size cap, a slop ratchet and tier-import checks are cheap to adopt for a Claude-built codebase; a 13-package workspace and hand-written build chains are not (our plan's ~9 packages already risk the same cost).
- [mcp-tool-surface] Their MCP server shows the directory-review constraints in practice: `annotations.title` duplicated from `title`, honest read/destructive hints, responses trimmed for the model (`compactModelCatalogForModel`: 440 KB catalog cut down), widgets switchable off by flag while the tool stays registered as a plain tool (`mcp/src/tools/platformTools.ts`, `showServers.ts`). Mirror: always return text + `structuredContent`; one feature flag to disable the panel.
