> Verified 2026-10-29 against primary sources: the npm registry, the spec repo `research/refs/mcp-spec` @ 9850cae (2026-10-28), the TS SDK `research/refs/mcp-typescript-sdk` @ 39ae8e6 (2026-10-27), `research/refs/ext-apps` @ 07cda25 (2026-10-27), `research/refs/mcpb` @ 70fe3b3 (= upstream main, 2026-04-22), host source code read with `gh api` (openai/codex, microsoft/vscode, aaif-goose/goose, zed-industries/zed), the official docs of Claude, Claude Code, OpenAI, Cursor and Devin Desktop, and the anthropics/claude-ai-mcp issue tracker.

## Key answers

1. **What does each host speak, and does it support 2026-07-28?** Dual-era (2026-07-28 with legacy fallback): Claude Code, Claude Desktop (local and remote), claude.ai, Goose and Devin Desktop/Windsurf. Effectively modern-only: ChatGPT, which has no `initialize` fallback per three reports. Legacy-only: Cursor (2025-11-25), VS Code Copilot (2025-11-25), Zed (2025-11-25) and Codex (2025-06-18 by default; 2026 support is behind an off-by-default flag). **The gateway must serve both eras.** SDK v2's `serveStdio`/`createMcpHandler` do this by default. Confidence high (source code and docs) for Claude Code, Codex, VS Code, Goose, Zed and Cursor; medium (issue logs) for Desktop, claude.ai and ChatGPT.
2. **Is any host modern-only?** ChatGPT, by reports. It follows that the v2 remote connector's `server/discover` must list `2026-07-28` and work under OAuth. Confidence medium. Sources: cahut#121, dozzle#5465, zotero-mcp#573.
3. **Does 2026-07-28 carry a session or conversation identifier?** **No.** The reserved request `_meta` keys are `protocolVersion`, `clientCapabilities`, `clientInfo?`, `logLevel?`, `progressToken`, `subscriptionId`, `traceparent`/`tracestate`/`baggage`. The spec says a process or connection must not be treated as a conversation, and state across calls must use explicit handles. Hosts add **vendor** keys instead: ChatGPT `openai/session`, VS Code `vscode.conversationId`, Goose `agent-session-id`. Claude Code has the `CLAUDE_CODE_SESSION_ID` **env var** only, frozen at spawn and not updated on `/clear`. claude.ai, Desktop, Cursor, Codex and Zed send none that I found. Confidence high. Sources: `schema.ts` l.63–110; `basic/index.mdx` l.186–209, 350–362; host sources in §7.
4. **Are server `instructions` still delivered in 2026-07-28, and how?** Yes, but **only in `DiscoverResult.instructions`**, and clients MAY skip `server/discover` (the spec only says a client "may invoke any RPC inline"). On legacy connections they arrive in `InitializeResult.instructions` as before. SDK v2 fills both from the `McpServer` `instructions` option. All the dual-era hosts call `server/discover` (Claude Code, claude.ai, Goose, ChatGPT), so in practice they receive them. Claude Code caps instructions at **4,096 characters** (since 2.1.296, previously 2,048; configurable with `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH`) and loads them at session start even with tool search. OpenAI: "ChatGPT and Codex use these instructions alongside tool metadata." Confidence high. Sources: `server/discover.mdx`; `schema.ts` l.678–697; `packages/server/src/server/server.ts` l.947–968; code.claude.com/docs/en/mcp l.493–520; developers.openai.com/plugins/build/mcp-server.
5. **Which hosts render MCP Apps today?** Claude web, Desktop (chat and the Code tab), iOS and Android; ChatGPT; VS Code Copilot; Cursor; Goose; M365 Copilot; plus Postman and MCPJam. **Not:** the Claude Code CLI, Codex (flag off), Zed, MCP Inspector, fast-agent. Windsurf/Devin Desktop is unknown. Confidence high. Sources: `mcp-spec/docs/extensions/client-matrix.mdx`, Claude design guidelines, Desktop changelog, Codex `features/src/lib.rs`, Zed source.
6. **Current npm versions?** server/client/core 2.4.0 (2026-10-23); node 2.1.2; hono and express 2.0.2; fastify 2.0.1; sdk v1 1.32.2 (maintained, 2025 era only); ext-apps 2.0.4 (2.1.0 was published and reverted, so avoid it); mcpb 2.1.2 (2025-12-04). Confidence high. Source: npm registry.

## Implications for ADRs

- [dual-protocol] Serving both eras is required. Legacy-only hosts are Cursor, VS Code, Zed and Codex; ChatGPT appears modern-only. Use `serveStdio(factory)` (default `legacy:'serve'`) and `createMcpHandler(factory)` (default `legacy:'stateless'`). Never `legacy:'reject'`, never a hand-wired `StdioServerTransport`. Run the CI wire tests in both eras.
- [dual-protocol] Codex speaks **2025-06-18**, not 2025-11-25, so the legacy path must accept 2025-06-18 (the SDK does). Don't depend on any 2025-11-25-only feature such as URL elicitation or icons for Codex.
- [dual-protocol] Make the factory cheap and side-effect free. Claude Desktop and Claude Code spawn a short-lived **sibling probe process** that only sends `server/discover`. The SDK calls the factory twice on the probe-fallback path.
- [session-definition] The protocol has no session. Use a host-agnostic **server-minted receipt/session handle** passed as a tool argument as the source of truth. Then upgrade to host keys where they exist: ChatGPT `_meta["openai/session"]`, VS Code `_meta["vscode.conversationId"]`, Goose `_meta["agent-session-id"]` (plus `agent-working-dir`), Claude Code env `CLAUDE_CODE_SESSION_ID` (spawn-time only, stale after `/clear`; the hook `session_id` stays authoritative). Fall back to process lifetime plus an idle gap only as a label.
- [session-definition] One process per conversation is false almost everywhere: Claude Code stdio servers "outlive the session that spawned them"; Desktop runs separate copies for chat and for Cowork/Code; Codex is building cross-chat connection sharing. Key every receipt by the handle or host id, never by PID.
- [dashboard-process-model] Expect several gateway processes per host (Desktop chat + Cowork/Code pool + probe sibling, and doubled on the Windows Store build). This supports "every gateway writes to SQLite WAL, no single-instance lock in the gateway". Keep startup under 300 ms and idempotent.
- [mcp-tool-surface] Server `instructions` reach models only through `server/discover` (2026) or `initialize` (2025). Keep them ≤ 4,096 characters (the Claude Code cap) with the critical guidance first. Keep tool descriptions self-sufficient in case a modern client skips discover.
- [mcp-tool-surface] Add cache hints to `tools/list`, `resources/list`, `resources/read` (receipt UI) and `server/discover`, with a deterministic tool order. Claude Code fails on 2026 results that lack them.
- [mcp-tool-surface] Codex can pass `codex/sandbox-state` (with `sandboxCwd`) in `_meta` if the server declares the experimental capability `codex/sandbox-state`. Claude Code sets `CLAUDE_PROJECT_DIR`. Goose sends `agent-working-dir`. These are project-context inputs for `.searchhole.yaml` resolution that need no Roots (Roots is deprecated).
- [security] `apply_rule` with `visibility:["app"]` is only hidden on hosts that implement Apps. On the Claude Code CLI, Codex and Zed the model may see and call it. Either (a) omit app-only tools from `tools/list` when the request's `clientCapabilities.extensions` lacks `io.modelcontextprotocol/ui` (spec gray zone: the core spec says lists must not vary per connection, but capabilities are per request in 2026 and the Apps spec allows variants by host capability; legacy connections have capabilities per connection), and/or (b) require a short-lived, HMAC-signed user-action token that only the rendered panel holds. Do (b) regardless.
- [security] Never use form elicitation for API keys (spec). On claude.ai avoid **state-only** `input_required`, which it surfaces as an error (claude-ai-mcp#1027). Desktop Cowork drops elicitation (claude-ai-mcp#1046). "Ask first" therefore needs the text-plan fallback everywhere.
- [lists-subscriptions] Hosts handle `list_changed` poorly: Desktop ignores it on `subscriptions/listen` (claude-ai-mcp#1182), and Codex's `mcp_tool_list_changed` is off. Keep the tool set static. Rule and list changes must never change `tools/list`.
- [ui-ux] The MCP Apps receipt panel reaches Claude web, Desktop and mobile, ChatGPT, VS Code, Cursor and Goose. Claude Code CLI, Codex and Zed users get only text + `structuredContent`, so the text receipt must be complete. Size the receipt for Claude's ~150k-character delivery limit and Claude Code's 25k-token default. The CSS token count is 76. Don't set `ui.domain` for the local gateway. `frameDomains` is restricted in Claude.
- [runtime-packaging] `.mcpb` (manifest 0.3, Node server) runs on Desktop's bundled Node, whose version is undocumented, so ship a single bundled JS file with no native modules. A Claude Code plugin can point `mcpServers` at the same `.mcpb` (path or HTTPS URL), which makes option (c) viable. The SDK needs Node ≥ 20.
- [distribution] The Claude directory no longer accepts MCPB submissions: distribute the `.mcpb` directly and reach the directory through a plugin. For OpenAI's directory, remove hooks (confirmed: "Remove lifecycle hooks before public directory submission"). A ChatGPT connector needs public HTTPS (the tunnel is for testing only).
- [engine-adapter] Not affected.
- [testing] Add a host-emulation matrix to e2e tests: a legacy client at 2025-06-18 (Codex), a legacy client at 2025-11-25 (VS Code, Cursor, Zed), a dual-era client with a sibling probe (Claude Code, Desktop), and a modern-only client with no fallback (ChatGPT). Assert `resultType` and cache hints, vendor `_meta` passthrough (`openai/session`, `vscode.conversationId`, `agent-session-id`), and that a `server/discover` probe has no side effects.
- [other] Pin `@modelcontextprotocol/ext-apps@2.0.4` exactly: 2.1.0 is on npm but was reverted. Pin `@modelcontextprotocol/server/client/core@2.4.0` with matching adapters (`node@2.1.2`, `hono@2.0.2`). Re-check monthly: the SDK releases every 1–3 weeks.
