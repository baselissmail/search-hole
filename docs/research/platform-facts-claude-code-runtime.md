# Platform facts: Claude Code plugins/hooks, other hosts, runtime/SQLite/packaging

Verified 2026-10-29 against live primary sources: code.claude.com docs fetched as `.md`, the Claude Code changelog, the npm registry, the GitHub API, nodejs.org, the Bun repo at tag `bun-v1.4.4`, developers.openai.com, cursor.com, agentskills.io and agent-plugins.org. Local checks: `claude --version` / `plugin --help`, and `node -e "require('node:sqlite')"` on the Node versions installed.

Scope: MASTER_PLAN §3 "Claude Code plugins and hooks" and "Other hosts" (Codex, Cursor, Skills), §4 "Runtime availability", "SQLite driver", "Bundling", "Session", and the runtime part of §12.1.

**Headline changes vs the plan**

1. **The Claude Code docs moved.** Plugin pages now live under `code.claude.com/docs/en/plugins/…`: `manifest-reference`, `components`, `loading`, `marketplace-reference`, `cli-reference`. The old `marketplace-reference` URL returns 404. Update §15 C.
2. **The MCP server learns its Claude Code session.** Stdio servers get `CLAUDE_CODE_SESSION_ID` (since v2.1.154) and `CLAUDE_PROJECT_DIR`, so the session ADR gets much simpler.
3. **Hooks can call our MCP server directly.** A `type: "mcp_tool"` hook (since v2.1.118) needs no extra node process. If the server isn't connected, the hook fails open by design.
4. **"OS secure store" holds on macOS only.** Sensitive `userConfig` goes to the macOS Keychain; on other platforms it goes to `~/.claude/.credentials.json`.
5. **The reserved-name rule is wider than the plan says.** `claude plugin validate` reports these names as errors, but Claude Code still installs and loads the plugin.
6. **`node:sqlite` is a release candidate (no warning) from Node 24.15 and in Node 26.** It is still experimental, with a warning, on Node 22. Node 26.11 renamed `DatabaseSync` to `Database` and kept the old name as an alias.
7. **better-sqlite3 13 moved to N-API.** It ships 8 prebuilds inside the npm tarball and has no install script.
8. **Bun 1.4.4 implements `node:sqlite`.** Compiled Bun binaries are about 90–110 MB per platform.
9. **Codex's public directory won't list search-hole as a local stdio plugin.** Local MCP submissions are limited to approved partners, so "hookless" alone doesn't get a plugin listed.
10. **The local Claude Code (2.1.97) is about 215 releases behind latest (2.1.312).** It lacks `plugin eval`, `validate --strict` and `--json`.

## Key answers

1. **Does natively installed Claude Code put `node` on PATH for MCP servers and hooks? What do the docs recommend? Is there a per-platform binary mechanism?**
   - **No.** All install methods (even npm) ship a native binary that doesn't invoke Node, and Claude Code supplies no runtime. The docs' only guidance is "install it, or make sure it's on the `PATH` of the terminal you start `claude` from". Every plugin MCP example uses `"command": "node"`, and auto dependency install uses npm or bun from the user's PATH.
   - **No per-platform binary mechanism is documented.**
     - `bin/` is added to the **Bash tool's** PATH only, after the user's own entries, and makes the plugin uninstallable on claude.ai and Cowork.
     - An MCP `command` can be any absolute `${CLAUDE_PLUGIN_ROOT}/…` executable, but it's one string for all platforms.
     - `.mcpb` paths and URLs are accepted, but no bundled runtime is documented for them.
   - New escape hatch: `mcp_tool` hooks let the gateway serve the hooks, so only one process needs a runtime.
   - Confidence: high. Sources: code.claude.com/docs/en/setup (npm section), plugins/troubleshooting, plugins/components#executables, plugins/manifest-reference, hooks#mcp-tool-hook-fields.
2. **Marketplace plugin source types: is there an `npm` source, and how does it install?**
   - **Yes:** `{"source":"npm","package":"…","version":"^x","registry":"https://…"}`. It is fetched with the **user's npm client** via `npm pack --ignore-scripts` with an integrity check (v2.1.275+). Install scripts never run.
   - Dependencies install in a separate step only from `npm-shrinkwrap.json` or `bun.lock`, with `--ignore-scripts`, exact registry versions and a 60 s timeout.
   - git, folder, `file:` and `npm:` aliases are refused, as are tarball URLs on github.com and gitlab.com. With no `version` set, the computed version is `unknown`, so set it in `plugin.json`.
   - The other sources are relative path, `github`, `url`, `git-subdir`, `archive` (https zip ≤ 256 MiB, `sha256`) and `command`.
   - Confidence: high. Sources: plugins/marketplace-reference#npm-plugin-source, plugins/loading, changelog 2.1.275.
3. **Hook I/O; node scripts; Windows; quoting.**
   - **Input:** `session_id`, `prompt_id`, `transcript_path`, `cwd`, `scratchpad_dir`, `permission_mode`, `effort`, `hook_event_name` (plus `agent_id`/`agent_type`). PreToolUse adds `tool_name`, `tool_input` (WebSearch: `query`, `allowed_domains`, `blocked_domains`) and `tool_use_id`. Stop adds `stop_hook_active`, `last_assistant_message`, `background_tasks`, `session_crons`.
   - **Output:** `hookSpecificOutput.{hookEventName, permissionDecision (allow/deny/ask/defer), permissionDecisionReason (shown to Claude on deny), updatedInput (replaces the whole input), additionalContext}`, plus the universal `continue`, `stopReason`, `systemMessage` (shown to the user), `terminalSequence`. **`suppressOutput` now has no effect.** Strings are capped at 10,000 characters.
   - Node scripts: yes, preferably in **exec form** (`command: "node"`, `args: ["${CLAUDE_PLUGIN_ROOT}/…"]`), which needs no quoting with spaces.
   - Windows: shell form runs under Git Bash, or PowerShell when Git Bash is absent. Without Git Bash, a failing shell-form PreToolUse hook **blocks** the call. Use `onFailure: "continue"` (v2.1.295+) to keep it fail-open.
   - Confidence: high. Source: code.claude.com/docs/en/hooks.
4. **Does the spawned MCP server get anything identifying the session?**
   - **Yes, by env var:** `CLAUDE_CODE_SESSION_ID` (v2.1.154+), plus `CLAUDECODE=1` and `CLAUDE_PROJECT_DIR`.
   - **No** `CLAUDE_SESSION_ID`, and no `_meta` field.
   - Caveat: the server keeps its spawn-time ID after `/clear`, and may keep the startup ID on `--continue` or `--resume` without an explicit ID. Re-key from hook `session_id` (a SessionStart `mcp_tool` hook runs after `/clear`).
   - Confidence: high. Sources: code.claude.com/docs/en/env-vars, changelog 2.1.154 and 2.1.163, mcp.md.
5. **`CLAUDE_PLUGIN_DATA`, sensitive `userConfig`, plugin `settings.json`, the name rule.**
   - **Data dir:** per plugin id (`name@marketplace`, sanitized) at `~/.claude/plugins/data/<id>/`. It survives updates and is **deleted (with options and secrets) on uninstall from the last scope** unless `--keep-data`.
   - **Sensitive values:** macOS Keychain, falling back to `~/.claude/.credentials.json`; that file is the only store on Linux and Windows.
   - **Plugin `settings.json`:** only `agent` and `subagentStatusLine` take effect.
   - **Names:** the `claude-`, `anthropic-`, `anthropics-` and `cc-plugin-` prefixes, a few exact names, and "official"+claude are validate **errors**; a whole-word "claude" is a warning. Claude Code still loads such plugins.
   - Confidence: high. Sources: plugins/manifest-reference, plugins/cli-reference, settings-reference#pluginconfigs.
6. **Node release status and `node:sqlite` stability.**
   - **Node 26:** Active LTS since **2026-10-28** (v26.13.0 "Lithium"), EOL 2029-04-30. `node:sqlite` is 1.2 RC, and `DatabaseSync` was renamed `Database` in 26.11.
   - **Node 24:** maintenance since 2026-10-20, EOL 2028-04-30. `node:sqlite` is 1.2 RC since 24.15.0.
   - **Node 22:** maintenance, EOL 2027-04-30. `node:sqlite` is 1.1, experimental with a warning.
   - **Node 25:** EOL 2026-06-01. `node:sqlite` was RC since 25.7.
   - Local test: **24.14.1 prints the ExperimentalWarning; 24.16.0 and 24.21.0 do not; 22.23.2 does; 20.20.2 has no `node:sqlite`.**
   - Confidence: high (Node 26 runtime warning behaviour inferred from RC status, not run). Sources: nodejs.org docs per version, nodejs/Release schedule.json, dist/index.json, local runs.
7. **better-sqlite3 latest, and Node 26 prebuilds?**
   - **13.0.3** (2026-08-05), N-API since 13.0.0, so prebuilds are Node-version independent and cover Node 26.
   - Eight prebuilds ship inside the npm package (darwin, linux glibc, linux musl and win32 × x64/arm64). There's no install script, and `engines` is node ≥ 22.
   - Confidence: high (tarball inspected). Sources: npm tarball, the GitHub v13.0.0 release notes.
8. **Bun, Node SEA, Deno.**
   - **Bun 1.4.4** (2026-10-22): 8 compile targets including windows-arm64 and both musl targets; `bun:sqlite` and **`node:sqlite`** are both supported. The runtime is 88.7 MB (darwin-arm64) and 107 MB (linux-x64), so expect about 90–110 MB per executable; `--trim` is unreleased.
   - **Node SEA:** still 1.1 Active development. `--build-sea` since 25.5. ESM and VFS in 26. No macOS x64 or Alpine in CI. About 113–122 MB.
   - **Deno 2.9.8:** 6 targets, no musl.
   - Confidence: high for versions and targets, medium for size (runtime size measured; app overhead not measured). Sources: Bun repo at tag, release assets, nodejs SEA docs, docs.deno.com.
9. **Codex and Cursor plugin formats.**
   - **Codex:**
     - Root `plugin.json` with the Agent Plugins 1.0.0 `$schema`, and root `mcp.json` with an explicit `type` per server.
     - `${PLUGIN_ROOT}` and `${PLUGIN_DATA}` expand in `args`, `env` and `cwd`, not in `command`. Codex-specific settings go under `extensions.com.openai`.
     - Hooks are allowed only for manually installed desktop plugins and **disqualify a plugin from the public directory**. Local stdio MCP plugins are "Desktop only" and **limited to approved partners** anyway.
     - Codex also reads `.claude-plugin/marketplace.json`.
   - **Cursor:** `.cursor-plugin/plugin.json` plus `mcp.json` plus `hooks/hooks.json` (Cursor's own event names). It expands `${CURSOR_PLUGIN_ROOT}` and `${CLAUDE_PLUGIN_ROOT}` (not `${PLUGIN_ROOT}`) in `command`, `args`, `env` and `cwd`. It also loads Agent Plugins packages, and secrets use `variables`.
   - Confidence: high. Sources: developers.openai.com/codex/plugins/build, developers.openai.com/plugins/deploy/desktop-only, cursor.com/docs/reference/plugins, agent-plugins.org/plugin-authors/mcp-servers.

## Implications for ADRs

- [session-definition] Use `process.env.CLAUDE_CODE_SESSION_ID` (Claude Code ≥ 2.1.154) as the initial session key, and `CLAUDE_PROJECT_DIR` for the project. Re-key when a hook reports a different `session_id`: a SessionStart(clear/compact) `mcp_tool` hook, a Stop `mcp_tool` hook, or a command hook that writes to the DB. Drop the "receipt id read back from the transcript" idea. Keep the server-minted `receiptId` from the mcp-spec note as the cross-host handle, and process lifetime plus idle gap for Desktop and others.
- [runtime-packaging] Recommend option (a+): require Node ≥ 22.13 (floor ≥ 24.15 after Node 22's EOL on 2027-04-30), ship one dependency-free bundled `gateway.js`, and make the experience loud:
  - `doctor`;
  - a SessionStart command hook (exec form, `onFailure: "continue"`) that detects missing or old node and prints `systemMessage` guidance;
  - a skill note about the 15-minute reconnect skip.

  Keep a Bun-compiled binary (option b) as a P8 experiment pending `--trim` and a first-run downloader. Each binary is about 90–110 MB, which rules out committing 8 of them.
- [runtime-packaging] Don't put executables in top-level `bin/` if claude.ai/Cowork installability matters. Reference CLI scripts by `${CLAUDE_PLUGIN_ROOT}/…` paths instead.
- [sqlite-driver] Prefer `node:sqlite` behind a 20-line adapter: `Database ?? DatabaseSync`, and `--disable-warning=ExperimentalWarning` on Node 22. It now covers Node 22/24/26 **and** Bun 1.4.4, so the driver choice no longer forces the packaging choice. Keep better-sqlite3 13 as a documented fallback: N-API, prebuilds in the tarball, no install script, `nativeBinding` for bundled layouts.
- [dual-protocol] Claude Code can still connect on 2025-11-25 (v1 runtime, env overrides, server-specific flags), so the gateway must serve both eras. This matches the mcp-typescript-sdk note.
- [mcp-tool-surface] Server `instructions` always load and tool definitions are deferred under tool search, so budget `instructions` carefully and consider `_meta["anthropic/alwaysLoad"]` on `search`. The `fetch` 8k-token pages sit well under Claude Code's 25k-token cap and its 50k-character persist threshold.
- [mcp-tool-surface] Evaluate a hook-only tool (e.g. `hook_pretooluse`, `hook_stop`) that `mcp_tool` hooks call. It removes a node process from the hook path and makes "deny only while healthy" exact, because the gateway itself answers. The cost is one visible tool name.
- [security] Fail-open contract for hooks: exec form, `onFailure: "continue"`, short timeouts. On Windows without Git Bash, a crashing shell-form PreToolUse hook blocks tool calls. `mcp_tool` hooks fail open when the server is down.
- [key-storage] Don't claim "OS keychain" for Claude Code `userConfig` on Linux or Windows (it's `~/.claude/.credentials.json`). `doctor` should flag `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` and `CLAUDE_CODE_MCP_ALLOWLIST_ENV` when a key looks configured but isn't visible.
- [upgrades-migrations] Old plugin versions keep running from their cache directory for up to 14 days after an update, and auto-update is off by default for third-party marketplaces. Plan for long version skew on the shared DB, and surface "newer version available" in `doctor` and the receipt.
- [distribution]
  - Claude Code: a GitHub marketplace with committed bundle output, or an `npm` source (needs npm on PATH and `version` set in `plugin.json`).
  - Codex: same repo (it reads `.claude-plugin/marketplace.json`, or `.agents/plugins/marketplace.json`), installed manually. The public OpenAI directory isn't reachable for a local stdio plugin without partner approval.
